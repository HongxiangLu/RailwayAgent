# 桥梁知识图谱问答系统（Flask）

入口：`app/run.py`；聊天页面：`app/static/index.html`；导入脚本：`app/import_graph.py`。

## 安装与配置

在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 .\app\run.py
```

浏览器访问 http://localhost:5000 。

配置位于项目根目录 `.env`，参考 `.env.example`；已有配置不要覆盖。
Flask 和导入脚本共用根目录配置，按脚本位置定位，已有进程环境变量优先。

- `NEO4J_URI`、`NEO4J_USERNAME`、`NEO4J_PASSWORD`：数据库连接。
- `NEO4J_DATABASE`：数据库名，默认 `neo4j`，须与导入目标一致。
- `OPENAI_API_KEY`：必填，缺少时启动报错。
- `OPENAI_BASE_URL`、`OPENAI_MODEL`：模型地址和名称。

问答由大模型在第一次调用中分类：工程验收业务问题生成 Cypher → Neo4j 查询 → 模型根据结果回答；明确无关的普通问题跳过数据库，由模型直接回答，并标注“通用回答（未查询知识图谱）”。两次调用均使用非思考模式，分类不增加模型调用次数。
模型调用或查询失败通过 `error` 事件报告；不降级为规则问答。
空查询结果也交给模型说明未找到数据，不允许补造验收标准。

浏览器标签页会生成 `conversation_id`，服务端在内存中保存最近 10 轮完整问答。历史同时用于理解本轮查询中的省略和指代，以及组织最终回答；工程条款和参数值仍只以本轮图谱查询结果为准。点击页面右上角「新对话」可清空记忆。服务重启也会清空全部会话。

## 图谱结构

Excel 的「分部工程类别」「分部工程子类别」分别导入为图谱标签「工程项目类别」「工程项目子类别」。图谱层级依次为：单位工程、工程项目类别、工程项目子类别、分项工程、最多四级施工质量验收标准细目。
空层跳过，层级之间使用 `包含`，指标通过 `包含指标` 挂到最后一个非空层级。
指标属性包括 `id`（记录编号）、`name`、`检验项目类型`、`规范条款`、`是否可量化指标`、`参数取值范围`。
指标原始字段中的规范条款仍作为属性保留，并通过 `依据` 关系连接到规范图谱中的 `条款` 节点；取值范围不是独立节点。记录编号仅用于图谱内部维护，不进入查询返回数据和问答；模型通过工程及细目层级路径区分同名指标。

「条款总表」导入为：准则 → 一级标题 → 二级标题 → 三级标题 → 项目类别 → 条款；空标题和「-」跳过。条款下分别包含「条款内容」「表格」「图片」节点。程序按条款正文中的「含表格/含图片」标注读取「检验表格」和「图片」工作表；表格保存为 Markdown，图片提取到 `app/static/standard_media`，条款内容的备注同时保留 PDF 页码、表题、图题和图片地址。指标属性中的 `[A]` 对应「高速铁路桥涵工程施工质量验收标准」，`[B]` 对应「铁路混凝土工程施工质量验收标准」，解析出的单条、并列条款和连续条款范围通过 `依据` 关系连接到条款节点。

## 数据导入注意事项

`app/import_graph.py` 可以直接运行，不需要先启动 Flask 问答服务。脚本会按自身位置自动定位项目根目录和 `.env`，并读取 `EXCEL_PATH` 和共用的四个 Neo4j 配置项：
`NEO4J_URI`、`NEO4J_USERNAME`、`NEO4J_PASSWORD`、`NEO4J_DATABASE`。
`EXCEL_PATH` 未配置时默认使用 `data/知识图谱260924.xlsx`；两套规范默认读取 `data/TB10752-2018高速铁路桥涵工程施工质量验收标准.xlsx` 和 `data/TB10424-2018铁路混凝土工程施工质量验收标准.xlsx`。配置相对路径时以项目根目录解析，也支持绝对路径，与启动目录无关。Neo4j 数据库服务仍需处于运行状态。
运行前会检查文件存在及密码已配置。

```powershell
.\.venv\Scripts\python.exe -X utf8 .\app\import_graph.py
```

运行会全量清空并重建目标数据库，并可能回写 Excel 记录编号；执行前请核对 `.env` 中的目标库。

导入时自动为六类节点的 `name` 创建非唯一 TEXT 索引，保留 `id` 唯一约束；索引进入 `ONLINE` 状态后可供查询使用。

## 接口

| 接口 | 功能 |
| --- | --- |
| GET / | 聊天页面 |
| GET /health | Neo4j 连通性检查（不验证模型） |
| POST /ask | JSON：`{"conversation_id":"浏览器会话ID","question":"明挖基础包含哪些分部工程？","limit":20}` |
| DELETE /conversation/&lt;conversation_id&gt; | 清空指定会话的多轮记忆 |

每次问答在终端输出 `[问答计时]` 日志，记录生成查询、数据库查询、生成回答及总处理耗时（毫秒），以及取回和返回行数；未执行阶段为 `null`，不记录问题、答案或凭据。总耗时覆盖响应流处理，可能包含流发送等待，不代表浏览器渲染完成。

没有 `/docs` 和 `/stats`。当前使用 Flask 开发服务器并开启 debug，供本地调试。
模型输出的查询尚无完整语句级权限校验；提示词中的只读要求不能替代数据库只读权限。

前端结构：`app/static/index.html` 保留页面，样式位于 `app/static/chat.css`，交互位于 `app/static/chat.js`，无需前端构建工具。
`POST /ask` 的有效请求现在返回 SSE 事件流（通过 fetch POST 读取），不再返回完整 JSON：
`status` 表示阶段，`delta` 为回答片段，`done` 携带 Cypher 和公开数据（普通问答为 `null` 和 `[]`），`error` 表示失败。
参数错误仍返回 HTTP 400 JSON。收到 HTTP 200 不代表问答完成，必须收到 `done`；中途断开或错误会显示回答未完成。
仅第二次模型调用流式输出，Markdown 每约80毫秒刷新并在结束时完整渲染。
计时在响应流结束/关闭时记录，新增“回答首段等待（毫秒）”，从回答调用开始计时；总处理耗时可能包含流发送等待，不代表浏览器渲染完成。

## Commit 规范

后续提交统一使用以下格式，类型使用小写英文，摘要使用简洁中文；范围可省略：

```text
<type>[(scope)]: <摘要>

<可选正文：修改原因、主要行为变化和验证结果>
```

冒号后保留一个空格。摘要应描述具体改动，避免使用「修改代码」「更新」等无法说明内容的表述。一次提交围绕一个完整目的组织，相关代码、测试和文档可以一起提交；互不相关的功能或修复应拆分。

| 类型 | 使用场景 |
| --- | --- |
| `feat` | 新增功能，例如支持规范图片查询 |
| `fix` | 修复缺陷，例如纠正条款与表格的关联 |
| `docs` | 修改 README、使用说明或其他文档 |
| `refactor` | 重构代码，不改变对外功能或修复缺陷 |
| `perf` | 改善查询、导入或页面渲染性能 |
| `test` | 新增或调整测试 |
| `style` | 仅调整代码格式、缩进等，不改变行为；页面视觉功能调整按实际目的使用 `feat` 或 `fix` |
| `build` | 修改依赖或构建配置，例如 requirements.txt |
| `chore` | 其他维护工作，例如调整 .gitignore 或开发工具配置 |

范围用于说明受影响的模块，可使用 `import`（图谱导入）、`assets`（图表提取）、`qa`（问答与查询）、`web`（前端）、`config`（配置）等。跨模块但属于同一目的的提交可以省略范围。

```text
feat(assets): 支持从规范工作簿提取条款图片
fix(import): 修正附录条款的表格关联
fix(qa): 保留数据库连接失败的底层异常
feat(web): 增加条款附件折叠展示
docs: 补充项目首次运行与日常启动步骤
test(qa): 增加明确条款查询的回归测试
chore: 忽略本地虚拟环境和临时文件
```

提交前请检查以下内容：

- 使用 `git status` 和 `git diff --cached` 检查实际暂存内容，避免夹带无关文件。
- 不提交 `.env`、API 密钥、数据库密码、虚拟环境或临时日志；配置示例仅使用占位值。
- 涉及 Excel 数据、生成图片等文件时，确认其确实属于本次变更且适合入库，避免误提交备份或重复产物。
- 根据改动执行必要的验证，并同步更新受影响的使用说明。
